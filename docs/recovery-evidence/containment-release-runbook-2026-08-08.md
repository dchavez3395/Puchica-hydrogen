## Manual extension-free QA

Browser-control extensions inject an extra element below `<html>` and can
replace the favicon before React hydrates. Both the Codex in-app browser and
the connected Chrome extension reproduced hydration warnings caused by those
injections. The server HTML itself contains only `<head>` and `<body>` at the
document root, so extension-controlled console output is not sufficient to
clear or condemn hydration.

Complete this pass in a normal phone browser or a desktop Incognito/Guest
window with extensions disabled:

1. Open the LAN or private Oxygen preview.
2. Open the console before first load on desktop; reload once.
3. Confirm there are no hydration, uncaught JavaScript, CSP, or failed-resource
   errors.
4. Review widths 320, 375, 390, 428, 768, 1024, and 1440 pixels. Confirm no
   accidental horizontal scrolling, clipped text, overlap, or inaccessible
   controls.
5. Keyboard-only: use Tab from the address bar, activate the skip link, traverse
   header/navigation/market controls, open and close the mobile menu, and verify
   a visible focus indicator throughout. Escape must close an open drawer and
   focus must return to its trigger.
6. Zoom to 200%. Confirm content reflows without loss of text or controls.
7. Apply the WCAG text-spacing values (line height 1.5, paragraph spacing 2em,
   letter spacing 0.12em, word spacing 0.16em) and confirm no clipping or overlap.
8. With NVDA or VoiceOver, confirm one H1, sensible heading order, useful link
   names, announced menu state, landmarks, and no focusable hidden content.
9. Check English, French, Spanish, and Portuguese holding pages for language,
   layout, and working information/policy links.
10. Recheck the containment route table above. No product card, product search,
    cart, checkout, campaign, merchant feed item, or catalog sitemap entry may
    escape containment.

Record the browser/version, device, route, result, screenshot path, console
result, and reviewer/date. Any hydration error in an extension-free browser is
a release blocker.

## Production hold and eventual release

Production remains a separate, explicit decision. Do not merge to `main`,
connect auto-deploy, change domains, or run `hydrogen deploy --env production`
until all of the following are true:

- the private/LAN preview was approved on desktop and mobile;
- extension-free hydration and the manual WCAG checks passed;
- the recovery branch is clean, committed, pushed, and attributable;
- production environment variables were compared with the required variable
  names without exposing their values;
- rollback target and production smoke-test owner are recorded;
- the user explicitly approves the production containment deployment.

Ads and catalog reopening remain separate gates. Deploying containment does not
approve a supplier, product, checkout route, campaign, or advertising spend.

  scoped inside the non-containment loader path. `SITE_URL` is now module-scoped;
  the contained feed returns HTTP 200 with zero products.
- A launch-readiness unit test depended on wall-clock time and failed when its
  fixture aged past seven days. The evidence evaluator now accepts an injected
  clock for deterministic tests; the production default remains the current
