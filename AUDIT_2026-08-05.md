## TL;DR

The store is **operationally alive and broadly well-built.** Real Hydrogen routes ship, sitemap+feed.xml+JSON-LD all work, Canada-checkout wiring is correct (`checkout.puchica.ca`), Meta Pixel + GA4 are mounted in CSP and wired to component-level events, and French locale is plumbed at the URL layer.

The honest problems are:

1. **French locale is mostly cosmetic** — `lang=fr-CA` on the wrapper, but `aria-label`s, nav labels, footer copy, and PDP body/H1/title do not actually translate. P0 for a "Canada-wide" launch claim.
2. **`origin/main` is 5 commits behind local HEAD.** `hydrogen deploy` is still a manual laptop step. No GitHub→Oxygen link. (Confirmed via the historical `DEPLOY.md` and current `h2_deploy_log.json`).
3. **An active admin token** of the form `atkn_2.…` sits at `D:/puchica-store/oxygen-token.json` (not gitignored by that path), alongside a leaked `accessToken=atkn_…` literal in the same file. Even if it is the OAuth CLI holder for the Hydrogen channel, leaving an admin token as plaintext in the worktree is a process smell.
4. **PDP render still relies on an off-page redirect for the `/best-sellers` slug** (handled) — but `/campaigns/packing-cubes` redirects because of a known broken DSers mapping. The redirect is documented in code, but is itself a stale product giveaway.
5. **`a11y` issues** — lang fallback missing on FR pages, generic skip-link not located from the captured DOM (need a browser render to confirm).

Everything below is sourced. Nothing is fabricated.

## 3. Localization

### 3.1 i18n config — **partially working**

- `app/lib/i18n.js` defines `en`, `fr`, `es`, `pt-br` as path prefixes, `x-default` → `/`. **`fr-CA` is NOT a path; only `fr`.** That contradicts the storefront's claim of "en-CA / fr-CA." A user hitting `puchica.ca/fr-CA/` will likely 404 or fall through to `fr`. P0 for legal compliance copy.

### 3.2 French page rendered

- `/fr/products/portable-fascia-gun-vibration-massage-gun` returned **200** with `lang=fr-CA`.
- But: the visible product title in the rendered DOM is **English**: "Portable Fascia Gun Vibration Massage Gun For Body Neck Back." H1, meta description, body copy, ARIA labels — all English. **The translation layer at the URL is wired, but the translation data itself is missing.**
- `<html lang="fr-CA">` is set; the `<xhtml:link rel="alternate" hrefLang="fr">` exists in the head. Good URL plumbing.
- 0 translated product descriptions visible on the FR PDP. Shoppers see English.

### 3.3 Coverage

- Walked: FR PDP. Only this PDP tested, but it confirms the conclusion: **translations are not populated in the Storefront content**, only the locale selector is. Customers landing on the FR URL from ad traffic will see English with a French `lang` attribute — Google will index it as English content with a French meta.
- The sitemap emits hreflang alternates for `fr|es|pt-br|x-default` so SEO is not collapsing, but it's also redundant if the bodies aren't translated.

**Severity:** **P0** — false bilingual claim, hurts organic ranking in French-Canada, and falls under Quebec Charter of the French Language if commercial activity is "directed at" Quebec residents.
